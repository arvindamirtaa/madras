# madras

A simple directory of food establishments in Chennai, with Wi-Fi, power socket and work friendliness information.

**Website:** https://madras.arvindamirtaa.workers.dev/

Cloudflare Workers serves the plain HTML, CSS and JavaScript in `public/` and a small API in `src/worker.ts`. Cloudflare D1 stores the listings. The frontend has no framework or build step. Wrangler bundles and deploys the Worker.

## Run locally

Install the development tools, initialize the local D1 database, and start the Worker:

```sh
npm ci
npm run db:local
npm run dev
```

Then visit http://localhost:8173. Local development uses a local D1 database; it does not modify the production database. The Google Fonts typeface and external links need a network connection. Development and tests were verified with Node.js 26.

## Update the directory

Each row in the D1 `places` table describes one establishment location. The requested fields are:

| Database field | Meaning |
| --- | --- |
| `name` | Establishment name |
| `area` | Chennai area or neighbourhood |
| `address` | Street address |
| `wifi` | `1` yes, `0` no, `NULL` unknown |
| `power_sockets` | `1` yes, `0` no, `NULL` unknown |
| `work_friendliness` | A short qualitative note, or `NULL` when not reviewed |

The table also retains a record ID, establishment type, short description, website and source URLs. `migrations/0001_places.sql` creates the schema and seeds the eight initial establishments. Venue details were sourced on 12 October 2026; Wi-Fi, sockets and work friendliness were not verified and start as unknown. This is an initial directory, not a complete list of Chennai establishments.

Update records in Cloudflare's D1 console, or add a new SQL migration in `migrations/`. Keep source links and only mark amenities as confirmed after checking them. Do not edit migrations that have already been applied. The API orders listings by name and caches responses for up to 60 seconds.

`GET /api/places` returns `{ "places": [...] }`. The API represents Wi-Fi and sockets as `true`, `false` or `null`, and uses `powerSockets` and `workFriendliness` for the two corresponding JSON field names. The public API supports reading only; data changes use the authenticated D1 console or Wrangler.

Search matches names, areas, descriptions, types, addresses and work notes. Search, area and establishment type filters work together.

## Hosting

`wrangler.jsonc` configures the `madras` Worker, static assets and the `madras-db` D1 binding. To deploy changes using the connected Cloudflare account:

```sh
npm run check
npm test
npm run db:remote
npm run deploy
```

Source changes are versioned in the public GitHub repository. Deployment uses Wrangler; a Git push alone does not deploy the Worker. Binding types are generated by `npm run check` and are ignored by Git. Local D1 state, environment files and credentials are also excluded from the repository.

The old GitHub Pages homepage redirects to the Cloudflare website.

The beach photograph attribution and license are recorded in `assets/README.md` and credited in the page footer.
